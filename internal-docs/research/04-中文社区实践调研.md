## 1. 精选文章深度要点

### 1.1 《Vue组件库 | 如何从0到1开发一个开源组件库》— Varlet 作者 耗子君QAQ（2021，43.4k 阅读，784 赞）

来源：https://juejin.cn/post/7010553100222070792

- **动机**：公司对现有库设计风格不满意 + 有升级 Vue3 计划 → 个人开源组件库（Varlet，移动端，现 4000+ star）。
- **先学习主流方案**：vant、vuetify、element(-plus)、material-ui、muse-ui 的架构思想，再定自己的实现。
- **Monorepo 拆包**（yarn workspace + lerna → 后切 pnpm）：通用依赖单独成包、独立发布；lerna 管发包依赖关系。
- **Design System 是前提**：没有设计系统不建议开工；个人可用成熟开源设计系统（Material / Vercel Design）。
- **组件库必备工具清单**：开发调试环境、按需引入、umd+esm 编译、文档站、单元测试、桌面/移动端预览、lint 规范、自动化部署与测试。Varlet 自研了 **Varlet-Cli** 管理整个生命周期（已开源）。
- **组件开发流程**：原型草稿 → 评审 → 重写 → 定 API → 补文档 → 单测 → 发布；"不要畏惧重写和推翻"。
- **测试**：jest + @vue/test-utils（当时），覆盖率托管 codecov。
- **发布**：semver；没底气先发 alpha/beta/rc。
- **CI**：GitHub Actions 跑测试、同步 gitee、部署文档。
- **社区治理**：PR/ISSUE 模板 + 贡献指南。

### 1.2 《Vue3 组件库设计 | 分享 Varlet UI 开源组件库的架构思路》— Varlet 作者（2023 更新，架构演进版）

来源：https://juejin.cn/post/7287419040666337335

- **pnpm monorepo 拆包实践**：varlet-cli（命令行）、varlet-eslint-config、varlet-icons（图标打包）、varlet-shared（通用工具）、varlet-ui（本体）、varlet-ui-playground（演练场）、varlet-use（组合式函数）、varlet-vite-plugins、varlet-vscode-extension——**一个组件库 = 一个解决方案生态**。
- **先设计稿再实现**（血的教训）：先实现组件后补设计资源，后期被迫全组件视觉修正 + 破坏性变更。
- **组件编写风格**：SFC 为主（编译时优化、运行时性能好）+ TSX 互补（VNode 操作更顺手）。
- **开发环境**：Webpack5 → **Vite**（开发服务器 + 库编译二合一，"自建组件库文档的不二之选"）。
- **图标**：字体图标方案（svg 集 → 字体文件 + css）。
- **测试**：jest → **Vitest**（与 Vite 共享配置、更快、少维护配置）。
- **编译器**：浏览器场景 TS 库用 **tsup**（esbuild 内核，比 tsc 快很多）；组件编译自研（babel 处理 vue jsx + esbuild 编译降级）。
- **产物**：esm（按目录结构输出，对按需引入最友好）+ cjs + umd（Vite lib mode 出 cjs/umd 捆绑）。
- **文档部署**：Vercel（PR/commit 自动预览，适合组件视觉审查）+ Gitee Pages（国内）。
- **演练场 Playground**：魔改 Vue 官方 playground，用于复现 bug/反馈。
- **VSCode 插件**：语法提示、文档跳转、Playground 集成、图标预览。

### 1.3 《写开源组件库需要知道些什么》— 嘿壳（2022，React 视角但流程通用）

来源：https://juejin.cn/post/7131980358844678180

- **组件技术选型**：
  - 样式方案（css-in-js / css modules / BEM / shadow DOM）按团队选一种，**不要混用**；
  - JS 语言建议直接 TS（接口类型 + 代码质量）。
- **API 定义是最重要的**（比性能/体积更重要）：受控非受控命名（value/defaultValue/checked）、回调命名（onChange/onClick/onSelect）、透传 props、尺寸/类型风格统一；**早期不要开放太多接口**（一旦开放就是维护负担）。
- **文档**：storybook / react-styleguidist 自动读取组件定义生成；或文档系统人工维护；需支持 props 表格 + demo 演示。
- **构建/发包**：输出 esm/cjs/umd + sourcemap + 类型定义；注意 browserlist、babel/postcss 兼容；package.json 的 files/版本/依赖/协议/tree-shaking 字段。
- **测试**：方法单测 + UI 行为测试（如 disabled 按钮不触发 onClick、select 点击弹层）；快照测试；像素测试慎用（图片占 git 空间）。
- **工具链**：eslint + prettier + stylelint + commitizen + husky/lint-staged + CI/CD（GitHub Actions）。

## 3. 对我们设计文档的印证与修正建议

| 社区共识 | 我们的设计 | 结论 |
|---|---|---|
| Monorepo 拆包是标准做法（pnpm） | pnpm workspace 三包（ui/create-kb/config） | ✅ 一致；可参考 varlet 拆出 shared/icons 子包（二期） |
| **先有 Design System 再写组件** | 已内置 token 体系（§4.4） | ✅ 一致；首版就应把 token 当作一等公民，避免"先实现后补设计"的坑 |
| 产物 esm 按目录 + cjs/umd | ESM+CJS（无 umd） | ⚠️ 补充：可选加 UMD 产物（Vite lib mode 顺手），满足 CDN 场景 |
| Vitest + @vue/test-utils | Vitest + @vue/test-utils | ✅ 一致 |
| tsup（esbuild）做 TS 库编译 | CLI 用 tsup | ✅ 一致 |
| SFC 为主 + TSX 互补 | 设计文档未提 TSX | ⚠️ 补充：VNode 重组件（如 Table 的 render 列）预留 TSX 能力即可，不强求 |
| API 规范早期收敛、少开放接口 | §4.3 已定义命名规范 | ✅ 一致；首版组件 props 应克制 |
| CLI 管理组件库生命周期 | create-kb 只做脚手架 | ℹ️ 可选：后续可把"新增组件模板"沉淀进 CLI（`kb add button`） |
| 文档站 + Playground 演练场 | Vitepress + playground | ✅ 一致（playground 已规划） |
| CI 自动测试/构建/发布 | GitHub Actions + changesets | ✅ 一致 |
| Vercel 预览 / Gitee Pages | 未定 | ℹ️ 文档站托管待定，Vercel 可作首选 |
