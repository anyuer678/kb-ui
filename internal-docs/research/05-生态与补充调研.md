### Arco Design Vue（2.58.0）
- 产物：`main: lib/index.js`、`module: es/index.js`、`types: es/index.d.ts`；unpkg 全量。
- 工具链：自研 `arco-vue-scripts`（build:component / build:style / dtsgen / icongen / lessgen / docgen / jsongen）——**把组件库生命周期全交给自研 CLI**（与 Varlet-Cli、我们的 create-kb 思路同源）。
- 样式：Less + 设计 token；`sideEffects` 含 `es/**/style/*`、`lib/**/style/*`、`*.less`。
- 依赖：dayjs、b-tween（动画）、b-validate（校验）、number-precision、@arco-design/color、scroll-into-view-if-needed 等——**小而专的依赖策略**。
- peerDependencies `vue >=3.1.0`；测试 jest（偏旧）；最近推送 2026-06-24（节奏放缓），open issues 921。

### Varlet UI（3.20.3）
- 产物：`main: lib/varlet.cjs.js`、`module: es/index.mjs`、`typings: types/index.d.ts`；style 字段 + umd。

### unplugin-vue-components 要点（消费端按需方案）
- 模板中直接用组件，自动按需 import + 注册；配合 `dts: true` 自动生成 `components.d.ts`（Volar 支持）。
- 内置 20+ 主流库 resolver（Element Plus/Naive/Arco/AntDV/TDesign/Vant/Varlet/Vuetify/PrimeVue/VueUse 等），也可写自定义 resolver。
- **对自研库的意义**：组件库只需保证 ESM 具名导出 + 按组件样式文件，用户侧按需体验由 unplugin 承担；我们可在文档站示例中演示自定义 resolver 写法。
- 注意：Webpack 的 CJS 支持在 29.1.0 后被移除。

## 3. 掘金补充文章（东方小月"从0搭建Vue3组件库"系列）

### 3.1 VitePress 搭建部署组件库文档（post/7201884082643632183）
- 标准做法：pnpm workspace 增加 `site` 目录 → 安装 vitepress + vue → `docs/.vitepress/config.js` 配 nav/sidebar → `docs/theme/index.js` 里 `app.use(组件库)` → md 中直接写组件 + `::: details` 折叠代码。
- 部署：GitHub Pages（`easyestui.github.io/easyest/`），**关键点：config.js 的 `base` 要配 `/easyest/`**，否则 404。
- 与我们设计文档的 Vitepress 方案完全一致，实施时按此套路即可。

### 3.2 一行命令搭建 Vue3 组件库框架 easyest（post/7315242945454866486）——与 create-kb 直接对标
- `npm create easyest` 脚手架生成 monorepo：`packages/components`（组件源码）+ `packages/easyest`（发布包）+ `play`（调试预览）。
- 组件目录规范：`button/_tests_`、`style/`、`button.vue`、`index.ts`（与我们设计的组件模板一致）。
- 发布流程：commit 规则校验 → `publish` 脚本交互式选择版本提升 → npm 登录 → 发布。
- 对照结论：**我们的 create-kb 设计（脚手架 + monorepo + play + 自动发布）与成熟开源先例一致**；easyest 偏组件库开发框架（面向组件库作者），create-kb 偏"脚手架 + 消费组件库"，可吸收其 publish 脚本交互经验。

## 4. 对设计的增量启示

1. **组件库生命周期工具化是共识**：Arco（arco-vue-scripts）、Varlet（varlet-cli）、easyest（脚手架+脚本）都把"开发/测试/打包/发布"沉淀为 CLI——我们的 create-kb 可扩展 `kb add <component>`（生成组件模板）与发布脚本，向"组件库开发框架"演进（一期先做脚手架）。
2. **依赖拆包策略**：@varlet/use、@varlet/icons、@varlet/shared 拆子包；我们二期可拆 `@kb/shared`（通用工具）、`@kb/icons`。
3. **按需消费由 unplugin-vue-components 统一解决**，组件库本身不做 babel 插件；文档站示例中提供 resolver 写法。
4. **测试选型再确认**：主流已全面切 Vitest（Varlet 3.20 用 vitest 4、Naive 用 vitest 3.2），@vue/test-utils 2.x 通用。
5. **GitHub Pages 部署文档站**时注意 base 配置；Vercel 无此问题（PR 预览更佳）。
