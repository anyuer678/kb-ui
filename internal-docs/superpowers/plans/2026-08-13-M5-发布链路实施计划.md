# M5 发布链路实施计划（changesets + CI + npm 发布）

> **For agentic workers:** Execute this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 建立完整的版本管理与发布链路：changesets（版本 + changelog）+ GitHub Actions（CI 校验 + 自动发布 PR + npm publish），使 `@kb/ui` 与 `create-kb` 可发布，且 `pnpm create kb` 生成的模板与组件库版本配套。

**Architecture:** 根目录安装 @changesets/cli；`.changeset/config.json` 配置；`pnpm changeset publish` 通过 changesets/action 在 CI 中执行（GitHub Token + NPM_TOKEN secrets）；发布包加 `publishConfig.access: public`；私有包（config/playground/docs）不发布。

**Tech Stack:** @changesets/cli、pnpm ≥ 10、GitHub Actions、npm OIDC（可选）。

## Global Constraints

- 发布包：`@kb/ui`、`create-kb`（均 `publishConfig.access: public`）。
- 私有包：`@kb/config`、`kb-playground`、`kb-docs`（不发布，changesets 不 bump 其版本）。
- baseBranch：`master`（当前 git 默认分支）。
- 首次发布：初始 changeset（minor：0.1.0 → 0.2.0）验证完整链路；`updateInternalDependencies: patch` 保证 create-kb 依赖的 @kb/ui 版本同步更新。
- CI（ci.yml）：checkout → pnpm/action-setup → setup-node(20, cache) → install --frozen-lockfile → lint → typecheck → test → build → changeset status。
- Release（release.yml）：master 推送触发，changesets/action 自动开版本 PR，合入后 `pnpm changeset publish` 发布两个包。
- 每任务提交（Conventional Commits）。
